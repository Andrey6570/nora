# Нора

Кооперативная игра для пары о быте и заботе друг о друге. Двое отмечают домашние дела, получают звёзды и копят их в общую
копилку. У дела может быть три этапа: **заметить → спланировать → сделать**, поэтому видна и невидимая работа: кто помнит,
организует и планирует.

- Вход через Google, в паре двое. Второй партнёр присоединяется по коду из шести символов.
- Русский, английский и греческий.
- Звёзды начисляет только сервер (Cloud Functions). Приложение отмечает этап, сервер проверяет его и начисляет звёзды.
- Данные хранятся в Firebase (Authentication, Firestore, Functions).

## Как это устроено

Веб-приложение на Vite и обычном JavaScript, упаковано в Android через Capacitor. APK собирает GitHub Actions
(`.github/workflows/android.yml`) после каждого изменения в `main`. Готовый APK публикуется на странице
[Releases / latest](https://github.com/Andrey6570/nora/releases/latest): откройте её на телефоне и скачайте `nora.apk`.

```
src/              интерфейс и логика
functions/        сервер: начисление звёзд, удаление пустой пары; economy.js общий с приложением
firestore.rules   правила доступа к базе
android/          проект Android (Capacitor)
test/             тесты логики, переводов и правил базы
```

## Первый запуск

Порядок важен: сначала Firebase, потом ключи в приложение и на GitHub.

1. **Firebase Console** → Add project. Проект называется `nora`, его идентификатор `nora-d2fdf` (он записан в `.firebaserc`).
2. Внизу слева тариф Spark → **Upgrade** → Blaze (нужна банковская карта). Он нужен для серверных функций. В Google Cloud →
   Billing → Budgets & alerts создайте бюджет на 5 € с оповещением по почте. Для пары-тестировщиков расходы будут
   практически нулевыми.
3. **Firestore Database** → Create database → регион **eur3 (Europe)** → Production mode.
4. **Authentication** → Get started → Sign-in method → **Google** → Enable.
5. **Project settings** → Your apps:
   - **Web app** (значок `</>`): скопируйте значения `firebaseConfig` в `src/config.js`;
   - **Android app**: package name `com.andrey6570.nora`, SHA-1 ниже. Скачайте `google-services.json` и положите его в
     `android/app/google-services.json`.
6. **Сервисный аккаунт для выкладки.** Google Cloud Console → IAM и администрирование → Сервисные аккаунты → создайте
   аккаунт `github-deploy` с ролью **Владелец** (Owner) в проекте, создайте ключ JSON.
7. **GitHub** → Settings → Secrets and variables → Actions → секрет `FIREBASE_SERVICE_ACCOUNT` со всем текстом ключа.
8. **Actions** → «Deploy Firebase» → Run workflow. Он прогоняет тесты, публикует функции и правила базы.
   Если первая выкладка остановилась на разрешениях Eventarc, подождите 5–10 минут и запустите её снова.

Ключ подписи `android/app/nora.jks` лежит в репозитории (как в Talent Foxes, репозиторий приватный). Им подписаны отладочная и
тестовая сборки, поэтому SHA-1 не меняется. Если репозиторий станет публичным, ключ нужно заменить. SHA-1:

```
A5:67:4B:11:C8:09:6A:92:B0:03:CB:AA:FC:6C:DD:34:4E:B4:73:BF
```

## Как работает пара

Первый партнёр создаёт пару и получает код. Второй вводит код и попадает в ту же пару. Третьего правила базы не пустят.
Код действует, пока пара существует: если партнёр вышел, он может вернуться по нему же. Оставшийся партнёр может сменить
код в настройках, тогда старый перестаёт работать. Когда из пары вышли оба, сервер удаляет её вместе со всеми данными.

## Звёзды

Звёзды за «сделать» = минуты ÷ «1 звезда = N минут» (по умолчанию 10) × сложность (1; 1,5; 2), не меньше 1.
«Спланировать» даёт половину, «заметить» одну звезду. Каждая звезда идёт и тому, кто её заработал, и в общую копилку.
Если дело сделали **вдвоём** (кнопка «Вдвоём» у этапа «сделать»), звёзды удваиваются и все идут только в копилку.

Отметка этапа — документ `pairs/{pair}/log/{дело}_{этап}_{период}`. Период — день для ежедневных дел, ISO-неделя для
еженедельных и `once` для разовых. Поэтому каждый этап за период может отметить только один из двоих и только один раз.
Сервер проверяет отметку (участник пары, дело существует, этап есть у дела, день не дальше суток от сегодняшнего) и
начисляет звёзды. Неверную отметку он удаляет. Если отметку отменить, звёзды вернутся.

## Данные в Firestore

```
users/{uid}                 pairId, name, lang, consent
invites/{код}               pid
pairs/{pid}                 members[2], names, inviteCode, scale, pet {kind, name}; balances, pot, xp, sigDay, games, decor,
                            flame {n, last, freezes}, active {uid: день}, stats {chores, together, signals, reveals, matches, bought} — только сервер
pairs/{pid}/tasks/{id}      title, minutes, difficulty, repeat (once/daily/weekly), full (три этапа)
pairs/{pid}/log/{id}        uid, day, at, once, together; stars — только сервер
pairs/{pid}/answers/{g}_{i}_{uid}  uid, game (guess/wishes), item, v, g — приватные ответы, читает только автор
pairs/{pid}/results/{g}_{i} game, item, answers (guess) или level (wishes) — только сервер
pairs/{pid}/coupons/{id}    from, title, at, used — купоны
pairs/{pid}/progress/intimacy30  start, done[] — «30 дней близости»
pairs/{pid}/rewards/{id}    title, cost, scope (personal/joint) — каталог наград пары
pairs/{pid}/orders/{id}     uid, kind (reward/game), ref, at, approvedBy, used; status, cost, title, joint — только сервер
pairs/{pid}/signals/{id}    from, kind (message/reaction), key, ref, day, at — тёплые слова и реакции
pairs/{pid}/devices/{id}    uid, token, lang — токен push этого телефона (читает только сервер)
```

## Push-уведомления

Push-уведомления работают в Android-приложении через Firebase Cloud Messaging. При первом открытии пары приложение просит
разрешение, получает токен и записывает его в `pairs/{pid}/devices/{id}` вместе с языком интерфейса. Функция
`signalCreated` проверяет сигнал (участник пары, известный ключ из `functions/signals.js`, дневной лимит в
`pair.sigDay`), отправляет push устройствам партнёра на их языке и удаляет токены, которые Google признал недействительными.
Токен удаляется при выходе из аккаунта или пары и при удалении аккаунта.

**Диагностика.** «Настройки → Уведомления» показывает состояние: нет разрешения, отклонено, ошибка (с причиной), токен
не сохранён, включено. Кнопка «Включить уведомления» запрашивает разрешение (Android 13+ спрашивает его явно) и работает
повторно; запрос повторяется и при возврате в приложение. «Отправить тестовое уведомление» пишет `test` в запись устройства,
функция `deviceUpdated` шлёт уведомление на этот телефон. Результат каждой отправки (`lastResult`: успех или код ошибки
Google) сервер пишет в запись устройства, ошибки попадают в журнал функций. Логика запроса разрешения вынесена в
`createPush` (`src/push.js`) и проверена тестами со всеми исходами. Разовая проверка боевого проекта (сколько устройств в
базе, какие ошибки в журналах; без токенов и имён): Actions → «Diagnose push».

## Политика, условия и удаление данных

Тексты политики конфиденциальности и условий использования (GDPR, ru/en/el) лежат в `src/legal.js`. Приложение показывает
их у галочки согласия и в «Настройках → Помощь и документы». Выкладка Firebase собирает из них публичные страницы
(`tools/build-legal.mjs`) и публикует на Firebase Hosting: https://nora-d2fdf.web.app/legal/ — этот адрес нужен для
анкеты Google Play.

**Перед публикацией в магазине** заполните выделенные места (имя или компания, адрес, почта) в `src/legal.js` и покажите
тексты юристу. Греческую версию должен прочитать носитель языка.

«Настройки → Удалить аккаунт» удаляет имя из пары, выводит из пары, удаляет профиль и запись входа (после повторного
входа через Google). Отметки остаются в истории пары с техническим идентификатором и удаляются вместе с парой.

Справка и частые вопросы — в `src/help.js`.

## iOS (Apple)

Проект iOS лежит в `ios/` (Capacitor, Swift Package Manager). Сборка на Mac-раннере GitHub: **Actions → iOS build → Run workflow** (минуты macOS стоят в 10 раз дороже Linux).

Что есть сейчас:

- **Сборка для симулятора без подписи**: проверяет, что проект компилируется. Артефакт `Nora-ios-simulator`. **Установить на настоящий iPhone нельзя.**
- **Подписанный IPA и загрузка в TestFlight** (галочка `signed`): работает только после того, как вы заведёте всё ниже.
- «Войти через Apple» на iOS (требование App Store 4.8), повторный вход тем же способом при удалении аккаунта, иконка 1024 и заставка из `tools/make-icons.mjs`, дизайн Liquid Glass.

Что нужно от вас (без этого IPA для iPhone собрать невозможно):

1. Apple Developer Program (99 $/год) и Team ID.
2. В developer.apple.com: App ID `com.andrey6570.nora` с включёнными Sign in with Apple и Push Notifications.
3. В App Store Connect: запись приложения и API-ключ с ролью Admin или App Manager (Key ID, Issuer ID, файл `.p8`). Сертификат и профиль заводятся автоматически через этот ключ.
4. В Firebase: добавить iOS-приложение с тем же Bundle ID, скачать `GoogleService-Info.plist`; включить провайдер Apple в Authentication.
5. Секреты репозитория: `APPLE_TEAM_ID`, `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_P8`, `IOS_GOOGLE_SERVICE_INFO_B64` (файл кодируется `base64`).

Push и вход через Google на iOS сделаны в коде, но на Mac не запускались. Для них нужно:

- загрузить в Firebase (Project settings → Cloud Messaging → Apple app configuration) ключ APNs `.p8` (Key ID и Team ID);
- положить `GoogleService-Info.plist` в секрет `IOS_GOOGLE_SERVICE_INFO_B64`: workflow сам допишет из него `REVERSED_CLIENT_ID` в `Info.plist`.

Push на обоих телефонах идёт через плагин Firebase Messaging (токен всегда FCM). Первая сборка на раннере может потребовать правок.

## Иконка и логотип

Логотип: лисёнок выглядывает из норы-холмика, над ним звезда. Он нарисован кодом в `src/logo.js`, и всё остальное
собирается из этого одного рисунка командой `node tools/make-icons.mjs` (нужен Playwright с Chromium; результаты лежат в
репозитории, для сборки приложения скрипт не нужен):

- Android: значки всех плотностей, адаптивный значок (рисунок внутри центрального круга, любая маска лаунчера покажет его
  целиком), «тематический» одноцветный значок (Android 13+), заставка (до Android 12 картинка, с Android 12 значок на
  кремовом фоне), белый силуэт лисёнка для уведомлений (`drawable/ic_stat_nora.xml`);
- сайт: `public/icon.svg`, фавиконка, `apple-touch-icon.png`; те же файлы попадают в страницы политики на Firebase Hosting;
- магазины: `branding/play-icon-512.png` и обложка `branding/feature-graphic-{en,ru,el}-1024x500.png` для Google Play,
  версия логотипа с названием для светлого и тёмного фона. Описание и цвета: `branding/README.md`.

## Языки

Исходный текст русский и служит ключом: английский лежит в `src/i18n-en.js`, греческий в `src/i18n-el.js`. Тест
`npm test` проверяет, что у каждой русской строки в `src/` есть оба перевода. Греческий написан нейтрально по роду, но
перед публичным выпуском его должен прочитать носитель языка.

## Разработка

```
npm install
npm run dev              # веб-версия в браузере; без Firebase откройте http://localhost:5173/?demo
npm test                 # логика экранов и полнота переводов
npm run test:rules       # правила базы на эмуляторе (нужна Java)
cd functions && npm test # серверная логика
npm run sync             # собрать веб и обновить android/
```

Демо-режим (`?demo`, а также `?demo=signedout`, `?demo=nopair`, `?demo=alone`) работает без Firebase и показывает все экраны
на примерных данных.

Сборка APK локально требует Android SDK и JDK 21: `cd android && ./gradlew assembleRelease`.
